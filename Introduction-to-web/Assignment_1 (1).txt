Q1. Explain the difference between frontend, backend, and full-stack development with suitable real-world examples.

Ans:

Frontend Development: Develops the part of the website or application that users can see and interact with. 
It focuses on User Interface and experience (UI/UX), where user interaction is possible, i.e. the user can directly interact with it.
Technologies used: HTML, CSS, JS, React, Angular, Vue, etc.

Backend Development: Develops the server-side logic, database, and APIs that work behind the scenes. 
It focuses on business logic, authentication, and database management. The user cannot directly interact with the backend.
Technologies used: Java, Python, Node.js, PHP, Spring Boot, Express.js, MySQL, MongoDB.

Full Stack Development: Works on both the frontend and backend of a web application. 
It focuses on complete application development, handling both the user interface and server-side operations.
Technologies used: A combination of frontend and backend technologies.

Real-World Example: An E-commerce Website (Amazon)
When a customer orders a product from Amazon, the customer first sees the website, i.e. the frontend.

Frontend:
•  Displays the product images, price, reviews, and "Add to Cart" button.
•  Everything you click or see on the screen is built by the frontend.

Backend:
•  Receives your order.
•  Checks whether the product is in stock.
•  Processes your payment.
•  Updates the database.

•  Sends an order confirmation.

Full-Stack Developer:
•  Can build both the shopping webpage (frontend) and the server/database that processes the order (backend).

Q3. Describe how a browser requests and displays a web page from a web server.

Ans:

1. URL entry: The user types a URL (e.g. www.example.com) into the browser's address bar.
2. DNS lookup: The browser contacts a DNS server to convert the domain name into an IP address.
3. Establishing connection: The browser opens a TCP connection with the web server at that IP address, often secured using SSL/TLS (HTTPS).
4. HTTP request: The browser sends an HTTP request asking for the web page (HTML file and related resources).
5. Server processing: The web server receives the request, processes it (and may query a database for dynamic content), and prepares a response.
6. HTTP response: The server sends back the requested HTML, CSS, JavaScript, and other assets (images, fonts, etc.).
7. Rendering: The browser's rendering engine parses the HTML and CSS, builds the DOM and CSSOM, executes JavaScript, and paints the final page on the screen.
8. Display: The fully rendered web page is displayed to the user.

Q5. Explain what a web server is and give examples of commonly used servers.

Ans:

A web server is software (often running on dedicated hardware) that stores, processes, and delivers web pages and other content to clients (browsers) in response to their HTTP/HTTPS requests. 
It listens for incoming requests, processes them, and sends back the appropriate response, such as an HTML page, image, or data.

Examples of commonly used web servers:
•  Apache HTTP Server – one of the most widely used open-source web servers.
•  Nginx – known for high performance and handling concurrent connections efficiently.
•  Microsoft IIS (Internet Information Services) – used mainly for Windows-based applications.
•  Node.js (with Express.js) – JavaScript-based server used for building fast, scalable applications.
•  Apache Tomcat – used for running Java-based web applications.

Q8. Explain the difference between static and dynamic websites. Provide an example of each.

Ans:

Static Website: A website whose content remains the same for every user and does not change unless a developer manually edits the code. 
It is built using only HTML and CSS (and sometimes basic JavaScript), and it does not interact with a database.
Example: A simple personal portfolio website or a company brochure page with fixed content.

Dynamic Website: A website whose content can change based on user interaction, input, or data stored in a database. 
It uses server-side programming languages along with a database to generate content in real time.
Example: An e-commerce website like Amazon or Flipkart, where product listings, prices, and recommendations change based on data and user activity.

Q9. Research and list five web browsers. Explain how rendering engines differ between them.

Ans:

A rendering engine is the part of a browser responsible for interpreting HTML, CSS, and JavaScript and converting them into the visual page a user sees.
•  Google Chrome – uses the Blink rendering engine (a fork of WebKit) along with the V8 JavaScript engine.
•  Mozilla Firefox – uses the Gecko rendering engine along with the SpiderMonkey JavaScript engine.
•  Apple Safari – uses the WebKit rendering engine along with the JavaScriptCore engine.
•  Microsoft Edge – uses the Blink rendering engine (Chromium-based) along with the V8 JavaScript engine.
•  Opera – also uses the Blink rendering engine, since it is built on the Chromium project.

Since Chrome, Edge, and Opera all use Blink, they render most web pages very similarly. Firefox (Gecko) and Safari (WebKit) may render certain CSS features,
fonts, or animations slightly differently, which is why cross-browser testing is important for web developers.

        v

        │  Passes request
        v

        v
